# Decision: 리포트 생성 정책 — 월 1회 제한 + 사용자 지정 기간 + 최소 데이터 요건

## Status

결정됨 (2026-07-02, `92f3dfa` 리포트 정책 변경)

---

## Context

초기 리포트 기능은 "생성 가능 횟수(쿼터)"를 보여주는 `QuotaStatusCard`와 단순 `GenerateButton`으로 구성됐다.

사용자는 몇 번 남았는지는 알 수 있었지만, 리포트가 어떤 기간을 분석하는지, 그 기간에 데이터가 충분한지는 생성 버튼을 눌러야 알 수 있었다.

AI 리포트는 유료 핵심 기능이다. 실패(데이터 부족으로 리젝)를 사용자가 버튼을 누른 뒤에 경험하게 하는 것은 신뢰를 깎는다.

---

## Problem

리포트 생성 정책을 어떻게 설계할 것인가?

가능한 방향:

1. 무제한 생성 허용 (AI 호출 비용 통제 불가)
2. 횟수 기반 쿼터만 유지 (기존 방식) — 기간과 데이터 충분성은 생성 시점에만 검증
3. "이번 달 1회" 게이팅 + 사용자가 분석 기간을 직접 고르고, 고르는 즉시 데이터 충분 여부를 미리 확인

---

## Decision

`ReportService`에 다음 정책을 적용한다.

### 1. 월 1회 생성 제한

캘린더 월(달력 1일~말일) 기준으로 `pending/processing/completed` 상태의 리포트가 이미 있으면 재생성을 막는다. 재시도가 필요한 실패(`failed`) 건은 제한에서 제외한다.

```
canGenerateThisMonth = 이번 달에 (failed가 아닌) 리포트가 없다
```

### 2. 사용자 지정 분석 기간 (7~90일)

`periodStart`/`periodEnd`를 사용자가 `PeriodCalendar`에서 직접 선택한다. `MIN_PERIOD_DAYS=7`, `MAX_PERIOD_DAYS=90`으로 제한하고, 반려동물 등록일 이전이나 오늘 이후는 선택할 수 없다.

### 3. 최소 데이터 요건 (10건 & 7일)

선택한 기간에 `HealthRecord`가 `MIN_RECORD_COUNT=10`건 이상, `MIN_RECORD_DAYS=7`일 이상 분산되어 있어야 생성 가능하다. `getReportPeriodPreview` 쿼리로 기간을 고르는 즉시(생성 버튼을 누르기 전) 충분 여부를 `PeriodValidityCard`에 실시간으로 보여준다.

---

## Reason

### 실패를 생성 이전 단계로 이동

`QuotaStatusCard`(횟수 안내)를 `PeriodValidityCard`(데이터 충분성 실시간 안내)로 교체했다. 사용자는 기간을 바꿔가며 "언제를 선택해야 리포트를 만들 수 있는지"를 생성 전에 파악할 수 있다. 실패 경험도 제품 경험이라는 원칙(`architecture.md` Error Handling)의 적용이다.

### 날짜 비교는 "달력상 하루" 단위로

`assertValidPeriod`는 `periodStart`/`periodEnd`/`petCreatedAt`/오늘을 모두 `toCalendarDay()`로 시각 정보를 제거한 뒤 비교한다. 프론트가 보내는 "day0 00:00~day6 23:59:59"(7일 선택)는 ms 기준으로는 7일에 살짝 못 미치고, 반려동물 등록 "시각"이나 현재 "시각"과 비교하면 정상적으로 오늘/등록일을 선택한 케이스도 거부될 수 있었기 때문이다.

### AI 호출 비용 통제

월 1회 제한은 AI 리포트가 유료 기능이라는 전제(`product-vision`)와 맞물려, 무제한 LLM 호출로 인한 비용 폭증을 막는 안전장치이기도 하다.

---

## Trade-off

- 월 중간에 실패(`failed`)해도 재시도 가능하도록 예외 처리했지만, "이번 달 리포트를 이미 확인했는데 다시 만들고 싶다"는 요구는 지원하지 않는다. 향후 유료 등급별로 월 생성 횟수를 늘리는 구조로 확장 가능하나 현재는 하드코딩된 상수(`MIN_RECORD_COUNT` 등)로 관리한다.
- 기간 유효성 검증 로직이 `report.service.ts`에 날짜 계산 주석과 함께 다소 방어적으로 작성되어 있다. 타임존 관련 버그를 겪은 뒤 추가된 방어 코드이므로 임의로 단순화하지 않는다.
